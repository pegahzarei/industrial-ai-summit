ヒューストン

Microsoft Innovation Hub に集ったオペレーター、CIO、Microsoft の産業部門リーダー。6つの講演と、実際のプラントデータによるライブデモンストレーションが行われました。

当日

11月4日、オペレーター、CIO、そして Microsoft の産業部門リーダーがヒューストンの Microsoft Innovation Hub に集い、産業オペレーションにおけるAI活用をテーマに一日を通して議論を交わしました。

鋭い質問が飛び交い、デモンストレーションはライブで行われ、議論は午後2時を過ぎても続きました。

このすべてにおいて鍵となるのは知識の保護です。もはやモデルではありません。モデルは現れては消えていきます。

Christoph BerlinMicrosoft エンジニアリング担当VP

講演

  1. 01

    プラントデータに必要なのは、より大きなモデルではなくナレッジグラフです。

    オープニング基調講演：産業AIにおける6つの成功要素

    語られたこと
    • オンボーディングに1年はかからなくなりました。約500の資産を持つ一般的なプラントのナレッジグラフ構築には、かつて9か月から18か月かかっていました。AIが P&ID、PFD、時系列データ、数万件の文書を読み取ることで、実用的なグラフが今では数日で完成します。
    • エグレスゼロなら、最も長い承認サイクルを回避できます。AIモデルを含む17のコンポーネントすべてが、顧客自身の Azure テナントにライセンス提供されます。何も外部に出ないため、エグレスが引き起こす3か月から6か月に及ぶ CIO、CISO、法務のレビューがそもそも始まりません。
    • フロンティアモデルはプラントデータでモダリティの崖から転落し、しかもコストは高くなります。テキストでは80から90%のスコアを出すモデルが、20枚の P&ID にまたがる接続性に関する質問には10%未満しか正答できませんでした。ドメインに特化して学習した小型モデルは10分の1から100分の1のコストで回答し、モデルが数分かけて推論するところを、グラフは数ミリ秒で回答します。
    デモを作りたいなら、大規模言語モデルで作ればよいでしょう。現場の50人のエンジニアに渡したいなら、ナレッジグラフを構築してください。
    Moe TanabianIntuigenceAI 創業者兼CEO
  2. 02

    誰も傍観はできません。賭けの数を絞り、規模を大きくしてください。

    基調講演：Chevron のデジタルトランスフォーメーションにおける重要なステップ

    語られたこと
    • 地図は半年ごとに変わります。互いに目印を残しましょう。競争領域でないものは共有し、他社の学びを取り入れてください。共に学ぶ業界団体は、どの企業が単独で進むよりも速く前進します。
    • 技術スタック、モデル戦略、パートナーを慎重に選んでください。人事アプリケーションに使うモデルは、時系列データで学習させるモデルとは異なり、地質学向けのモデルもまた別物です。道筋が違えば、必要なパートナーも違います。
    • 価値は削減時間ではなく、少数の大きな賭けで測ってください。従業員1人あたり週5時間の削減は、最終損益に表れないかもしれません。最良の成果は、具体的な指標を持つ明確に定義されたプロセスから生まれており、中には20倍のリターンを上げた例もあります。先進企業はそこに、より大きく長期的な賭けをしています。
    産業分野で、この道のりを歩まずに済む人は誰もいません。
    Bill BraunChevron 元CIO
  3. 03

    守るべきは知識です。モデルは移り変わります。

    基調講演：Microsoft Fabric による産業ユースケースのAI加速

    語られたこと
    • これはテクノロジースタックではなく、マインドセットです。これまでのあらゆる革命が仕事のやり方を変えてきたように、今回も同じです。シュトゥットガルトのある自動車メーカーでは、根本原因の調査に9か月かかり、その大半はデータを持つ人を探すことに費やされていましたが、今では数分でチームを証拠へと導いています。
    • データは今ある場所に置いたまま、その上に1つのガバナンス層をかけてください。問題は50のデータベースではなく、50通りの管理方法です。Microsoft Fabric をはじめとする統合データレイヤーは、オンプレミスを含め、それらを1つの方法で管理し、アクセスを制御します。
    • デジタル資産の境界に線を引いてください。あらゆるAIソリューションは、自社のテナンシー内、つまり信頼と知識の境界の内側にあるか、その外側で他者が自社の知識にアクセスできる状態にあるかのどちらかです。運用上の知識と組織の知識は内側にとどめ、決してモデルにさらさないでください。
    このすべてにおいて鍵となるのは知識の保護です。もはやモデルではありません。モデルは現れては消えていきます。
    Christoph BerlinMicrosoft エンジニアリング担当VP
  4. 04

    AIエンジニアに求めるのは答えではなく、完成した仕事です。

    製品紹介とライブデモ

    語られたこと
    • 会場が見守る中、図面がグラフになりました。データレイクから Microsoft Fabric 上の IntuigenceAI のワークロードに追加された未加工の P&ID が、すべての接続を保持したまま、シンボル、ライン、タグに解析されました。同じ図面を汎用モデルで扱うと、20枚の P&ID がコンテキストに入った時点でスコアは10%を下回ります。
    • AIエンジニアのチームが、温度が低下した蒸留塔の原因と考えられる箇所を突き止めました。プラントエンジニアのエージェントが、質問を化学、機械、E&I、APC、保全の各スペシャリストに振り分けました。彼らは計器とアラーム限界値、2基のスチームリボイラーを特定し、電話会議の中で、そのうち1基への供給を妨げている満液状態のコンデンセートドラムを指摘しました。
    • 1つの依頼が、繰り返し使えるワークフローになりました。蒸留塔のトラブルシューティング、シフトエンジニアへの通知、作業指示の発行、設定値を下回った際のアラート。これらがグラフから計画され、6時間ごとにスケジュールされ、テンプレートとして共有されました。エージェントは Microsoft Teams の通話にも参加します。
    違いは、精度、レイテンシ、コスト、そして「Chat AI」ではなく完成した仕事にあります。単に質問するのではなく、仕事そのものを依頼するのです。
    Pegah ZareiIntuigenceAI 製品担当VP
  5. 05

    競争の焦点は、誰が作れるかではありません。いかに早く価値にたどり着くかです。

    基調講演：フィジカルAIの成果

    語られたこと
    • データとのチャットはフェーズ1でした。フェーズ2は損益計算書です。それが実現するのは、ワークフローが部門をまたいでエンドツーエンドで動き、組織がそれを中心にフラット化したときだけです。ある企業は、各システムから1人ずつを1つの部屋に集め、スタートアップならどのように顧客に価値を提供するかを問い、その答えを軸に組織を再編しました。
    • パイロット止まりの停滞は、形を変えた分断です。各パイロットは1つの部門のデータとアプリケーションの中で何かを証明するだけなので、価値はその境界で止まってしまいます。大きな変化が始まるのは、部門とそのデータセットが連携したときです。
    • データは今ある場所でインデックス化してください。リフトアンドシフトはしないでください。データレイクが集約され、コンテキスト付けされる頃には、データはもう古くなっていました。データをその場で参照、ミラーリング、ショートカットすれば、ユースケースは数時間で立ち上がります。ある事業者は、2,500億の信号をエンジンに活用することで、50万トンの排出量を削減しました。
    持ち帰って、チームに試させるだけで終わらせないでください。ハッカソンを開催し、うまく機能していないプロセスの再構想を求め、CEO から表彰してもらうのです。
    Hany SolimanMicrosoft エネルギーおよび資源担当ゼネラルマネージャー
  6. 06

    AIのコストは掛け算で膨らみます。計画し、制御し、最適化してください。

    基調講演：産業AIでトークンをより少ないコストでより有効に活用する

    語られたこと
    • 4つのレバーは掛け合わされ、それぞれが10倍に動き得ます。インタラクション数、エージェントのステップ数、ステップあたりのコスト、トークン価格です。クラウドの FinOps が10%から20%を巡って争うのに対し、AIでは振れ幅が桁違いであるため、パイロットから作った計画が10倍ずれることもあります。
    • 月次予算は制御手段ではありません。静かな日曜日、失敗したヒストリアンの呼び出しを10秒ごとに再試行し続けたエージェントが、誰かがアラートを読む前に13億トークンを消費しました。30分以内に作動するサーキットブレーカーは、月次予算よりも約1,500倍優れています。
    • 失敗の代償が大きい所に投資し、それ以外はルーティングしてください。質問をナレッジグラフにグラウンディングすることで、15万トークンが7,000トークンに減りました。モデルルーティングを加えると、その差は42倍に達します。安全性とレジリエンスに関わる判断には最高のモデルを使い、定型的な質問は十分な性能のモデルに回してください。
    計画を誤れば、10倍ずれることがあります。制御を誤れば、ある日曜日の午後ひとつで予算が台無しになりかねません。最適化しなければ、予算は本来必要な額の50倍にもなり得ます。
    Adam BogobowiczMicrosoft シニアディレクター
